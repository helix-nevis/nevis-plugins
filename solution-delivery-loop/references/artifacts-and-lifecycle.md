# 产物与生命周期细则

在执行第零至第五步时按需读取。本文件规定长期信息如何保存，不要求机械创建全部文件。

## 一、典型产物结构

```text
├── 起点与约束.md
├── 需求基线.md
├── 方案.md 或 方案/
├── 工作规划.md
├── 待决与决策.md
├── 执行/
└── 验证记录/
```

这是信息结构，不是强制文件数量。小项目可合并为四份正文：起点与约束、需求基线、方案、工作规划；待决与决策并入工作规划，执行和验证记录按需产生。

### 需求基线的自然阅读顺序

```markdown
# 需求基线
## 一、概述
## 二、核心需求
## 三、业务规则与边界
## 四、统一语言
## 五、待讨论事项（引用统一清单）
## 六、需求追溯
```

不单建“人工版”或“智能体版”，也不专门制造人工对齐摘要。

### 方案的信息边界

```text
方案/
├── 产品交互方案.md
├── 领域模型.md
├── 技术方案.md
├── 开发规范.md
├── 契约/
│   ├── 接口设计.md
│   ├── 数据库设计.md
│   └── 外部服务契约.md
├── 决策记录.md（或引用统一决策入口）
└── 验证记录/
```

小项目可以合并。工作项、接口和数据库设计不得各自复制一套业务规则。

交互原则与布局决策归入《产品交互方案》，设计系统或项目已有规范仍是其权威来源，不在工作项和审计记录中重复维护。

## 二、贯穿信息的字段与关闭规则

### 待决与验证清单

至少记录：

- 稳定编号；
- 类型：待决策或待验证；
- 问题或假设；
- 发现来源；
- 阻塞或影响的需求、方案和工作项；
- 处理方式：人工判断、短探针或真实环境核验；
- 状态：开放、处理中、已关闭；
- 关闭后结论回填位置。

**关闭时必须把结论写回需求、方案、契约或工作项，清单只保留指针。** 否则清单会成为第二套事实源。

### 追溯关系

分段持有并串联：

```text
需求基线：需求 → 方案章节
工作规划：工作项 → 需求、方案依据
交付记录：任务 → 工作项、验收证据
```

不必集中维护大矩阵，但任一段都不能形成无法双向检查的断点。

### 决策记录

只收难以逆转、缺少背景容易令人意外且存在真实权衡的决定。只追加，保留当时背景、选项、代价、结论和影响；普通实现修正不进入重大决策记录。

## 三、生命周期表

| 产物 | 创建时机 | 更新条件 | 收尾方式 |
| --- | --- | --- | --- |
| 起点与约束 | 第零步，后续按需加深 | 发现新的现状事实 | 保留当前有效结论 |
| 需求基线 | 第一步 | 仅获批的需求变更 | 保留当前基线与必要变更记录 |
| 方案与契约 | 第二步 | 审计回填、执行偏差、外部假设被推翻 | 保留当前有效方案 |
| 待决与验证清单 | 全程 | 发现即登记，解决即关闭 | 结论回填正文，开放项保留，历史可归档 |
| 决策记录 | 按需 | 只追加 | 长期保留背景与权衡 |
| 工作规划 | 第四步 | 状态和批次变化 | 当前批次保留，历史批次归档 |
| 任务与交付记录 | 执行期 | 任务推进和关闭 | 保留证据索引，过程可归档 |
| 过程日志 | 按需 | 排查与交接需要 | 默认归档，不进入长期正文 |

## 四、归档判断

只有执行、验收、决策或变更仍依赖的内容才保留在长期阅读入口。中间讨论、失败尝试、工具调用、重复日志和已被覆盖的临时判断，可以在保留必要证据索引后归档。

归档不是删除所有历史：重大决策保留背景，交付保留证据索引，需求保留必要变更记录；但不把过程日志当作新的需求或方案正文。
