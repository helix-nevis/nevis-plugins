# 工作法行为回归

采用官方 prompt.md + graders/*.md 格式，共九个案例。仅使用合成内容，allowed_tools 不含 Bash、写入工具或外部服务。LLM grader 会产生额外模型费用，确定性工具 grader 不调用评分模型。

## 发现与执行分开检查

- `freshness-vs-schedule`：自然表达“按工作法分析”，测试是否发现并调用技能，以及分层与证据状态是否正确。
- `freshness-explicit-invocation`：明确要求通过 Skill 工具加载技能，使用同一业务输入和评分标准；额外检查是否用 Read 读取需求细则。它用于诊断加载后的执行，不能代替自然触发测试。
- 两例均检查技术实现与交互的区别，以及候选要求不得被写成已确认结论；允许不提出任何额外功能。

`skill-fired` 检查技能调用；显式案例中的 `requirements-read` 只证明发生了匹配读取，不证明理解或全文遵循，仍须结合语义评分。单臂模式下这些检查参与得分，不能把分数直接当作业务质量百分比。

首次单个案例、单臂一次运行，明确模型、预算与停止条件；不自动接入付费 CI。更改后建议先手动试跑显式调用案例，再试自然表达案例，均保留 `--keep-temp` 以检查工具轨迹，并用 `--no-publish` 保持报告本地。不自动重跑或扩大范围。模型评测通过也不证明真实 SubagentStart 事件已匹配。
